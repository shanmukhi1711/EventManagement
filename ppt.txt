## Slide 4: Problem Statement
VNR VJIET hosts diverse campus events, but fragmented manual communication via posters, emails, and word-of-mouth hinders student awareness and participation. Students struggle to discover events, register efficiently, and track their involvement, leading to missed opportunities for engagement and skill development. Event organizers face administrative burdens in managing registrations and generating certificates without a centralized system. This results in low participation rates and inefficient processes that impede campus culture and student growth.  

**Solution Needed:** A digital platform to streamline event discovery, registration, notifications, and certificate management, enhancing accessibility and fostering a vibrant community at VNR VJIET.

## Slide 22: Key Features
**Core Functionality:**  
- **Authentication:** JWT-based with Google OAuth integration  
- **Event Management:** Browse, filter, search events by category  
- **Registration System:** Online sign-ups with status tracking  
- **Notifications:** Automated alerts for upcoming events  
- **Certificates:** Dynamic generation and download (PNG)  
- **Profiles:** User dashboards with event history  
- **Admin Dashboard:** Event CRUD operations for organizers  
- **Responsive Design:** Mobile-first with PWA capabilities  

**Security:** Rate limiting, CORS, helmet middleware  
**Performance:** Optimized queries, caching, lazy loading

---

## Slide 23: Database Schema
**Users Table:**  
- id (TEXT PRIMARY KEY), email (UNIQUE), password, name, role (admin/candidate)  
- google_id, profile_image, created_at, updated_at  

**Events Table:**  
- id (TEXT PRIMARY KEY), title, category, date, venue, image, description  
- organizer, club, rules, contact_email, contact_phone, created_by (FK)  

**Registrations Table:**  
- id (TEXT PRIMARY KEY), user_id (FK), event_id (FK), registered_at  
- status (registered/attended), certificate_downloaded (BOOLEAN)  

**Notifications Table:**  
- id (TEXT PRIMARY KEY), user_id (FK), title, message, type, read, created_at

## Slide 32: Challenges & Solutions
**Authentication Integration:**  
- Challenge: Google OAuth with custom JWT  
- Solution: google-auth-library + separate user table  

**Real-time Notifications:**  
- Challenge: Automated scheduling  
- Solution: Node.js timers + database triggers  

**Certificate Generation:**  
- Challenge: Dynamic PDF/PNG creation  
- Solution: HTML5 Canvas API  

**Responsive Design:**  
- Challenge: Cross-device compatibility  
- Solution: Tailwind CSS + mobile-first approach
